# MerchantMate AI

**MerchantMate AI** is a conversational AI business assistant that helps small businesses manage PayPal invoicing and understand their financial activity using natural language.

Instead of navigating multiple dashboards and manually calculating invoice metrics, a business owner can ask MerchantMate questions such as:

```text
Create an invoice for Sarah for $350 for logo design.
```

```text
Show me my outstanding invoices.
```

```text
How much did I invoice this week?
```

```text
Who is my highest-value customer?
```

MerchantMate combines a local AI model with deterministic business logic and the PayPal Sandbox API. AI is used to understand the user's request, while financial calculations and PayPal actions remain controlled by validated backend code.

---

## Why MerchantMate?

Small-business owners often need to switch between invoicing tools, payment dashboards, spreadsheets, and reports just to answer simple questions about their business.

MerchantMate provides a conversational layer over these workflows.

It is designed around three principles:

- **Natural interaction** — ask business questions in plain English.
- **Safe financial actions** — invoice creation requires explicit user confirmation.
- **Deterministic financial logic** — AI interprets requests, but does not invent or calculate financial values.

## Core Features

### Conversational PayPal Invoicing

MerchantMate can interpret natural-language invoice requests such as:

```text
Create an invoice for Sarah for $350 for logo design.
```

It extracts structured information including:

- customer name
- customer email
- invoice amount
- currency
- description

If required information is missing, MerchantMate asks for it before continuing.

---

### Safe Invoice Confirmation

Financial actions are never executed immediately from an AI response.

MerchantMate first creates an invoice preview and requires explicit confirmation:

```text
User request
    ↓
Extract invoice details
    ↓
Validate required fields
    ↓
Show invoice preview
    ↓
Wait for explicit confirmation
    ↓
Create invoice in PayPal Sandbox
    ↓
Send invoice
```

Commands such as `cancel` stop the operation.

Ambiguous responses such as `maybe` do not execute financial actions.

---

### Duplicate-Invoice Protection

MerchantMate includes recovery logic for partial PayPal failures.

If PayPal successfully creates an invoice but sending the invoice fails:

1. MerchantMate preserves the existing PayPal invoice ID.
2. The conversation remains recoverable.
3. A retry sends the existing invoice.
4. MerchantMate does **not** create a duplicate invoice.

This protects the financial workflow from accidental duplicate actions.

---

### Invoice Management

MerchantMate can retrieve PayPal invoice information and help users:

- view invoices
- identify outstanding invoices
- inspect invoice status
- calculate outstanding invoice value

---

### Business Analytics

MerchantMate calculates business metrics directly from PayPal invoice data.

Supported analytics include:

- total invoiced
- outstanding amount
- paid amount
- average invoice value
- invoice count
- top customer
- business summary

Financial calculations are performed by deterministic Python functions rather than generated by the LLM.

---

### Period-Aware Analytics

Business questions can include time periods such as:

```text

```


Supported periods include:

- all time

The Streamlit interface provides a business snapshot containing:

The dashboard operates alongside the conversational assistant.

## System Architecture

```text
                         MerchantMate AI

                               User
                                │
                                ▼
                       Streamlit Frontend
                                │
                                ▼
                         FastAPI Backend
                                │
                                ▼
                     Assistant Orchestrator
                                │
                  ┌─────────────┴─────────────┐
                  │                           │
                  ▼                           ▼
             Ollama LLM                Business Router
                  │                           │
                  ▼                  ┌────────┴────────┐
          Structured AIIntent        │                 │
                  │                  ▼                 ▼
                  └──────────► PayPal Service     Analytics
                                     │                 │
                                     ▼                 │
                               PayPal Sandbox ◄────────┘
                                     │
                                     ▼
                              Validated Result
                                     │
                                     ▼
                                   User
```

The architecture intentionally separates AI reasoning from financial execution.

Ollama interprets the user's language and produces structured intent data. The backend then validates that data and decides whether to perform analytics, request missing information, require confirmation, or call PayPal.

---

## Safety Architecture

MerchantMate follows an important rule:

> **AI can propose a financial action, but validated backend logic decides whether it can execute.**

For invoice creation:

```text
Natural-language request
        ↓
Ollama intent extraction
        ↓
Pydantic validation
        ↓
Conversation state machine
        ↓
Invoice preview
        ↓
Explicit user confirmation
        ↓
PayPal execution
```

The LLM never directly calls PayPal.

The LLM is also not trusted to calculate financial totals.

## Application Workflow

### Example: Creating an Invoice

The user enters:

```text
Create an invoice for Sarah for $350 for logo design.
```

Ollama converts the request into structured intent data similar to:

```json
{
  "intent": "create_invoice",
  "customer_name": "Sarah",
  "customer_email": null,
  "amount": 350,
  "currency": "AUD",
  "description": "logo design",
  "requires_confirmation": true
}
```

Because the customer email is missing, MerchantMate asks the user for it.

After the missing information is supplied, MerchantMate prepares an invoice preview.

The invoice is **not** created yet.

Only after the user explicitly confirms the action does the backend call the PayPal service.

## Conversation State

MerchantMate maintains explicit conversation state for multi-turn financial workflows.

The state tracks information such as:

```text
pending_invoice
requested_field
awaiting_confirmation
paypal_invoice_id
```

This allows MerchantMate to safely handle conversations such as:

```text
User:
Create an invoice for Sarah for $250 for photography.

MerchantMate:
What is Sarah's email address?

User:
sarah@example.com

MerchantMate:
Invoice ready for confirmation.

User:
confirm
```

The backend remains stateless between API requests. The frontend sends the current conversation state with each request and receives the updated state in the response.

## Getting Started

### Prerequisites

Before running MerchantMate, install:

- Python 3.13
- Ollama
- Git

You also need PayPal Developer Sandbox credentials with access to the Invoicing API.

---

### 1. Clone the Repository

```bash
git clone https://github.com/DharunikaSivakumarSasikala/MerchantMate-AI.git
cd MerchantMate-AI
```

---

### 2. Create a Virtual Environment

```bash
python3 -m venv .venv
```

Activate it on macOS or Linux:

```bash
source .venv/bin/activate
```

On Windows:

```bash
.venv\Scripts\activate
```

---

### 3. Install Dependencies

```bash
python -m pip install -r requirements.txt
```

---

### 4. Install the Ollama Model

Pull the model used by MerchantMate:

```bash
ollama pull llama3.2:3b
```

Start Ollama if it is not already running:

```bash
ollama serve
```

MerchantMate expects Ollama at:

```text
http://127.0.0.1:11434
```

---

### 5. Configure Environment Variables

Copy the environment template:

```bash
cp .env.example .env
```

Configure:

```env
PAYPAL_CLIENT_ID=
PAYPAL_CLIENT_SECRET=
PAYPAL_BUSINESS_EMAIL=
PAYPAL_BASE_URL=https://api-m.sandbox.paypal.com

OLLAMA_BASE_URL=http://127.0.0.1:11434
OLLAMA_MODEL=llama3.2:3b
```

Never commit the real `.env` file or PayPal credentials.

## AI Integration

MerchantMate uses **Ollama with Llama 3.2 3B** for local natural-language interpretation.

The AI layer is responsible for:

- understanding natural-language requests
- identifying user intent
- extracting structured parameters
- interpreting business-query periods

The AI layer is **not** responsible for:

- calculating financial totals
- deciding whether confirmation can be bypassed
- directly calling PayPal
- inventing missing financial information
- storing PayPal credentials

This separation keeps AI useful without making it the authority over financial operations.

## Security Principles

MerchantMate follows several safety and security principles:

- secrets are stored in environment variables
- `.env` is excluded from Git
- PayPal credentials remain in the backend
- financial actions require explicit confirmation
- ambiguous confirmation does not execute an action
- user input is validated before financial execution
- Pydantic models validate structured application data
- financial calculations use deterministic Python logic
- the LLM cannot directly call PayPal
- failed invoice sends preserve the existing invoice ID for safe retry
- retries do not create duplicate PayPal invoices
- automated tests mock financial write operations where appropriate
- no payment card information is stored by MerchantMate

---

## Reliability Design

A financial assistant must handle partial failures safely.

For example:

```text
Create PayPal invoice
        ↓
     SUCCESS
        ↓
Send PayPal invoice
        ↓
     FAILURE
```

MerchantMate does not simply repeat the entire operation.

Instead:

```text
Preserve PayPal invoice ID
        ↓
Keep recoverable conversation state
        ↓
User retries
        ↓
Send existing invoice
        ↓
Do NOT create another invoice
```

This provides idempotency-style protection at the assistant orchestration layer.
